1. АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ
════════════════════════════════════════════════════════════════════════════════

1.1 Описание задачи

Веб-приложение "Администратор базы данных" предназначено для управления,
мониторинга и администрирования различных подключений к реляционным базам
данных (в частности PostgreSQL). Система позволяет пользователям:

- Добавлять и управлять подключениями к множеству баз данных
- Просматривать структуру таблиц и их метаданные
- Отслеживать выполнение запросов с логированием
- Управлять резервными копиями баз данных
- Контролировать доступ через систему ролей
- Отслеживать активность пользователей

1.2 Актуальность

В современных компаниях часто возникает необходимость управления несколькими
базами данных одновременно. Централизованная платформа администрирования
упрощает:

- Управление пользователями и ролями
- Мониторинг производительности
- Анализ логов запросов
- Создание резервных копий
- Оптимизацию структуры данных

1.3 Целевая аудитория

- DBA (администраторы баз данных)
- Разработчики (для работы с несколькими БД)
- IT-менеджеры (для контроля доступа)
- Системные администраторы

1.4 Ключевые требования

Функциональные требования:
✓ Регистрация и аутентификация пользователей
✓ Управление подключениями к БД
✓ Просмотр структуры БД (таблицы, колонки, индексы)
✓ Логирование запросов
✓ Управление резервными копиями
✓ Статистика и аналитика
✓ Интеграция с Redis для кэширования

Нефункциональные требования:
✓ Масштабируемость (асинхронная обработка)
✓ Безопасность (хеширование пароля, JWT токены)
✓ Производительность (кэширование, индексирование)
✓ Надежность (обработка ошибок)
✓ Удобство использования (интуитивный UI)

4. РЕАЛИЗАЦИЯ СЕРВЕРНОЙ ЛОГИКИ
════════════════════════════════════════════════════════════════════════════════

4.1 Аутентификация и авторизация

Механизм:
1. Пользователь регистрируется → пароль хешируется (bcrypt)
2. При логине проверяется пароль
3. Выдается JWT токен
4. Токен отправляется в каждом запросе в заголовке Authorization

Роли:
- ADMIN: полный доступ
- USER: управление своими БД
- VIEWER: только просмотр

4.2 Управление подключениями БД

Функции:
- create_database(): создание нового подключения
- test_connection(): проверка подключения к БД
- get_database_tables(): получение списка таблиц
- update_database_status(): обновление статуса подключения
- delete_database(): удаление подключения

Безопасность:
- Пароли хранятся в зашифрованном виде
- Проверка прав доступа на каждую операцию
- Логирование всех операций

4.3 Логирование запросов

Каждый запрос к БД записывается с:
- ID пользователя
- ID БД
- Текст запроса
- Статус выполнения
- Время выполнения (ms)
- Сообщение об ошибке (если есть)

5. РЕАЛИЗАЦИЯ СЛОЯ БД
════════════════════════════════════════════════════════════════════════════════

5.1 ORM Модели (SQLAlchemy)

UserModel
──────────
- Таблица: users
- Поля: id, username (unique), email (unique), full_name, hashed_password,
  role, is_active, created_at, updated_at
- Индексы: username, email
- Отношения: databases (1:N), query_logs (1:N), backup_logs (1:N)

DatabaseModel
──────────────
- Таблица: databases
- Поля: id, name, host, port, username, password, database_name, status,
  owner_id (FK), created_at, updated_at, last_checked
- Индексы: owner_id, (owner_id, name) unique
- Отношения: owner (N:1), tables (1:N), query_logs (1:N), backup_logs (1:N)

TableModel
───────────
- Таблица: tables
- Поля: id, name, database_id (FK), row_count, size_bytes, created_at,
  updated_at
- Индексы: database_id, (database_id, name) unique
- Отношения: database (N:1), columns (1:N), indexes (1:N)

ColumnModel, IndexModel, QueryLogModel, BackupLogModel
─────────────────────────────────────────────────────
- Аналогичная структура с соответствующими полями
